1. 为什么分流模式下普通查 IP 网站会“说谎”

绝大多数开发者并不会走全局代理，而是使用 分流（Split-tunneling）：国内网站直连，AI 域名走 Clash / sing-box / Xray 策略组。此时普通测速或查 IP 网站显示的往往只是直连出口或默认代理组，而不是 chatgpt.com 与 claude.ai 真正看到的出口 IP。

更隐蔽的问题是同平台多出口：当订阅策略开启了负载均衡或不同子域名命中了不同规则，chatgpt.com 走德国、auth.openai.com 走荷兰、api.openai.com 走美国。在 OpenAI / Anthropic 风控侧，这会被直接判定为同一账号同时在多个国家异地登录。

2. 如何精确看到 ChatGPT 和 Claude 看到的出口 IP

OpenAI、Anthropic、Perplexity、Grok、Mistral、Midjourney、OpenRouter 等主流 AI 平台几乎全部部署在 Cloudflare 后方，且各域名开放了支持 CORS 的 /cdn-cgi/trace 接口。浏览器直接访问 https://chatgpt.com/cdn-cgi/trace 或 https://claude.ai/cdn-cgi/trace 时，走的是与您日常对话完全一致的代理规则与节点：

fl=671f142
h=chatgpt.com
ip=203.0.113.42
ts=1763712000.123
loc=NL
colo=AMS
tls=TLSv1.3

三个关键字段一目了然：真实出口 ip、决定地区封锁的 loc，以及 Cloudflare 接入机房 colo。把同一平台的所有子域名（chatgpt.com、api.openai.com、auth.openai.com、sora.chatgpt.com）一起测一遍，立刻能看出有没有“节点分裂”。

3. IP 纯净度：为什么万人骑机场比独享 VPS 更容易风控

即使地区受支持，出口 IP 的历史信誉也直接决定验证码频率。多人共享的公共 VPN / 机场出口同时承载成百上千用户和自动化脚本，极易在风控库中积累高风险评分，导致频繁触发人机验证或账号受限。

同时，单一 IP 库常常误报：有的库把干净的个人 VPS 标成机房高风险，有的库把移动 CGNAT 误判成开放代理。更靠谱的做法是至少交叉对比 3 个独立数据源（如 ipquery.io、ipwho.is、ipapi.is）并结合 ASN 特征，在多源结果不一致时明确标出分歧。

4. 三个真实泄露与一个常见的 DNS 误区

  • WebRTC 通过 UDP 泄露：如果浏览器代理仅转发 TCP，WebRTC STUN 探测会绕过代理直接走 UDP 暴露真实本地 IP。解决方法是在代理客户端开启 UDP 转发，或在浏览器开启 mDNS / disable_non_proxied_udp。
  • IPv6 绕过代理隧道：不少代理配置只接管了 IPv4，让 IPv6 直接经本地宽带出去。支持双栈的网站（含 Cloudflare）就能通过 IPv6 看到真实地区，而只测 IPv4 的网站却显示一切正常。
  • 本地运营商 DNS 泄露：流量走海外节点，但 DNS 查询仍在本地运营商解析，不仅暴露访问域名，也会让风控发现 DNS 与 IP 地区不匹配。
  • 常见误区：“DNS 地区和出口 IP 不同就一定是泄露”。不对。如果使用的是公共 Anycast DNS（如 Cloudflare 1.1.1.1、Google 8.8.8.8、Quad9、NextDNS），解析会就近路由到最近节点，并不经过本地运营商，不属于运营商 DNS 泄露。

5. 浏览器本地一致性信号

  • 系统时间偏差（> 2 分钟）：会直接破坏登录令牌、2FA 校验，并与服务器时间形成明显异常。请保持系统自动 NTP 校时开启。
  • User-Agent 与 Client Hints 冲突：只改 UA 字符串却不更新 navigator.userAgentData 的插件，反而比正常浏览器更显眼。
  • navigator.webdriver = true：自动化框架（Playwright/Selenium）特征，日常使用建议使用常规浏览器配置文件。
